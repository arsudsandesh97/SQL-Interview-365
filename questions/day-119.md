# SQL Scenario-Based Interview Question: Identify At-Risk SaaS Subscriptions Due for Renewal

## Business Scenario
You are a Data Analyst at a growing SaaS company that offers various subscription plans. The Customer Success team wants to proactively identify "at-risk" customers whose subscriptions are due for renewal soon but who have shown low engagement recently. This information will enable them to reach out and re-engage these customers before their subscriptions expire.

Specifically, they need a list of active customers whose subscriptions are renewing within the next 30 days, AND who have had no activity (login, feature use, etc.) in the last 7 days.

Assume:
```sql
CURRENT_DATE = '2023-10-26'
```

---

# Database Setup

## Create customers Table
```sql
CREATE TABLE customers (
    customer_id INT PRIMARY KEY,
    customer_name VARCHAR(255) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL
);
```

## Create subscriptions Table
```sql
CREATE TABLE subscriptions (
    subscription_id INT PRIMARY KEY,
    customer_id INT NOT NULL,
    plan_id VARCHAR(50) NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    status VARCHAR(20) NOT NULL, -- 'active', 'cancelled', 'expired'
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
);
```

## Create customer_activity Table
```sql
CREATE TABLE customer_activity (
    activity_id INT PRIMARY KEY AUTO_INCREMENT,
    customer_id INT NOT NULL,

    activity_type VARCHAR(50) NOT NULL, -- e.g., 'login', 'feature_use', 'report_gen'
    FOREIGN KEY (customer_id) REFERENCES customers(customer_id)
```

# Task
Write a SQL query to identify "at-risk" customers. An at-risk customer is defined as:
1.  Has an `active` subscription.
2.  Whose `end_date` is within the next 30 days from `CURRENT_DATE`.
3.  AND who has no `customer_activity` recorded in the last 7 days from `CURRENT_DATE`. If a customer has no activity *ever*, they should also be considered at-risk under this condition.

Return the `customer_name`, `customer_email`, `subscription_id`, `plan_id`, `subscription_end_date`, and the `last_activity_date` for each identified at-risk customer. If a customer has no activity ever, `last_activity_date` should be `NULL`.
