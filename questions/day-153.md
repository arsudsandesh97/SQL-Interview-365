# SQL Scenario-Based Interview Question: Identifying At-Risk Downgrades Due to Inactivity

## Business Scenario
As a Data Analyst at 'CloudWave Solutions,' a SaaS company, you're tasked with identifying 'at-risk' customers who might be disengaging. A common hypothesis is that customers who downgrade their subscription plan often do so shortly after a period of reduced or halted feature usage. Your goal is to generate a report identifying all users who downgraded their subscription plan *and* whose last recorded feature usage occurred within 30 days *before* their downgrade date. This report will help the customer success team reach out proactively to understand the reasons behind these disengagement patterns and potentially intervene.

Assume:
```sql
CURRENT_DATE = '2023-10-26'
```

# Database Setup

## Create Users Table
```sql
CREATE TABLE Users (
    user_id INT PRIMARY KEY,
    username VARCHAR(100),
    signup_date DATE
);
```


## Create SubscriptionChanges Table
```sql
CREATE TABLE SubscriptionChanges (
    change_id INT PRIMARY KEY,

    plan_id INT,
    change_date DATE,
```

# Task
Generate a report listing all users who downgraded their subscription plan, but only if their last feature usage before the downgrade date occurred within 30 days of the downgrade.

The report should include the following columns:
1.  `user_id`
2.  `username`
3.  `downgrade_date`
4.  `previous_plan_name`
5.  `new_plan_name`
6.  `last_feature_usage_before_downgrade`
7.  `days_of_inactivity_before_downgrade` (the difference in days between `downgrade_date` and `last_feature_usage_before_downgrade`)

Order the results by `downgrade_date` in ascending order.

---
