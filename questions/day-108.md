# SQL Scenario-Based Interview Question: SaaS Subscription Optimization - Feature Usage Alignment

## Business Scenario
A rapidly growing SaaS company offers various subscription plans (Basic, Pro, Enterprise), each with different monthly fees and limits on key features, such as API calls. They want to ensure customers are on the most appropriate plan for their usage patterns to maximize customer satisfaction, minimize churn, and identify upgrade opportunities.

Your task as a Data Analyst is to analyze customer subscription data alongside their actual feature usage. The goal is to identify customers who, based on their API call usage in the *previous complete calendar month*, are either over-utilizing their current plan (suggesting an upgrade) or under-utilizing their current plan (suggesting a potential downgrade). For these customers, calculate the potential monthly revenue impact if they were to switch to an 'optimal' plan.

Assume:
```sql
CURRENT_DATE = '2023-10-26'
```

# Database Setup

## Create Customers Table
```sql
CREATE TABLE Customers (
    customer_id INT PRIMARY KEY,
    customer_name VARCHAR(100)
);
```


## Create Plans Table
```sql
CREATE TABLE Plans (
    plan_id INT PRIMARY KEY,
    plan_name VARCHAR(50),
    monthly_fee DECIMAL(10, 2),
    api_call_limit INT,
    tier_rank INT UNIQUE -- Helps to order plans by tier
);
```

## Insert Plans Data
```sql

(1, 'Basic', 50.00, 5000, 1),
(2, 'Pro', 150.00, 20000, 2),
```

## Create Subscriptions Table
```sql
CREATE TABLE Subscriptions (
    subscription_id INT PRIMARY KEY,
    customer_id INT,
    plan_id INT,
    start_date DATE,
    end_date DATE, -- NULL if subscription is currently active
    FOREIGN KEY (customer_id) REFERENCES Customers(customer_id),
    FOREIGN KEY (plan_id) REFERENCES Plans(plan_id)
);
```

# Task
Identify customers who are either "Upgrade Candidates" or "Downgrade Candidates" based on their 'API Calls' usage during the *last complete calendar month* (September 2023, given `CURRENT_DATE = '2023-10-26'`).

For each such customer, your output should include:
1.  `customer_id`
2.  `customer_name`
3.  `current_plan_name` (the plan active for them during September 2023)
4.  `current_monthly_fee` (of that current plan)
5.  `total_api_calls_last_month` (sum of 'API Calls' for September 2023)
6.  `candidate_type`:
    *   'Upgrade': If `total_api_calls_last_month` *exceeds* their `current_plan_api_call_limit`.
    *   'Downgrade': If `total_api_calls_last_month` is *less than or equal to* the `api_call_limit` of a *lower tier plan* than their current one, and such a lower tier plan exists.
7.  `suggested_plan_name`: The 'optimal' plan based on their usage.
    *   For 'Upgrade' candidates: The lowest-priced plan (with a higher `tier_rank`) that accommodates their `total_api_calls_last_month`.
    *   For 'Downgrade' candidates: The highest-priced plan (with a lower `tier_rank`) that accommodates their `total_api_calls_last_month` and is strictly cheaper than their current plan.
8.  `suggested_monthly_fee` (of the suggested optimal plan)
9.  `potential_monthly_revenue_impact` ( `suggested_monthly_fee` - `current_monthly_fee` )

Only include customers who are identified as either an 'Upgrade' or 'Downgrade' candidate.
