# SQL Scenario-Based Interview Question: Analyzing Subscription Plan Changes Upon Renewal

## Business Scenario
A leading SaaS company offers various subscription plans to its customers. The Product and Marketing teams are keenly interested in understanding customer behavior around subscription renewals. Specifically, they want to identify which customers change their subscription plan when they renew, and categorize these changes (upgrade, downgrade, or lateral move). This analysis helps them assess plan attractiveness, identify potential churn risks, and tailor marketing strategies. As a Data Analyst, you are tasked with providing insights into these renewal patterns.

Assume:
```sql
CURRENT_DATE = '2024-01-15'
```

---

# Database Setup

## Create Plans Table
```sql
CREATE TABLE Plans (
    plan_id INT PRIMARY KEY,
    plan_name VARCHAR(50) NOT NULL,
    monthly_price DECIMAL(10, 2) NOT NULL
);
```

## Insert Plans Data
```sql
INSERT INTO Plans (plan_id, plan_name, monthly_price) VALUES
(1, 'Basic', 10.00),
(2, 'Pro', 25.00),
(3, 'Premium', 50.00),
(4, 'Small Business', 25.00);
```

## Create Subscriptions Table
```sql
CREATE TABLE Subscriptions (
    subscription_id INT PRIMARY KEY,
    customer_id INT NOT NULL,
    plan_id INT NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    status VARCHAR(20) NOT NULL, -- e.g., 'active', 'expired', 'cancelled'
    FOREIGN KEY (plan_id) REFERENCES Plans(plan_id)
);
```

## Insert Subscriptions Data

# Task
Identify all instances where a customer renewed their subscription and changed their plan. A "renewal" is defined as a new subscription starting exactly one day after the previous subscription for the same customer ended. For each such renewal, determine the type of plan change:
1.  **'Upgrade'**: If the `monthly_price` of the new plan is higher than the previous plan.
2.  **'Downgrade'**: If the `monthly_price` of the new plan is lower than the previous plan.
3.  **'Lateral Move'**: If the `monthly_price` of the new plan is the same as the previous plan, but the `plan_id` is different.

Exclude new subscribers (those with no preceding subscription) and customers who did not renew their last subscription.
Your output should include `customer_id`, `previous_plan_name`, `new_plan_name`, and `change_type`.

---

| customer_id | previous_plan_name | new_plan_name  | change_type  |
|-------------|--------------------|----------------|--------------|
| 1           | Basic              | Pro            | Upgrade      |
| 2           | Pro                | Basic          | Downgrade    |
| 3           | Pro                | Small Business | Lateral Move |
