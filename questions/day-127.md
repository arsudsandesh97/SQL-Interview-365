# SQL Scenario-Based Interview Question: SaaS Customer Monthly Subscription Migration Analysis

## Business Scenario
A growing SaaS company needs to deeply understand customer behavior around their subscription plans. Specifically, they want to track how individual customers transition between different pricing tiers (e.g., Basic, Pro, Enterprise) on a monthly basis. This analysis is crucial for identifying churn risks, understanding the effectiveness of upgrade/downgrade incentives, and segmenting customers based on their journey through the product tiers. As a Data Analyst, you've been asked to provide a monthly report detailing each customer's subscription status change compared to the previous month.

Assume:
```sql
CURRENT_DATE = '2024-03-15'
```

---

# Database Setup

## Create customer_plan_history Table
```sql
CREATE TABLE customer_plan_history (
    customer_id INT,
    snapshot_month DATE, -- The first day of the month when the plan was active
    plan_name VARCHAR(50),
    plan_tier INT, -- Numerical representation of the plan's tier level (e.g., 1 for Basic, 2 for Pro, 3 for Enterprise)
    PRIMARY KEY (customer_id, snapshot_month)
);
```

# Task
Write a SQL query that generates a report showing each customer's monthly subscription status change. For each customer and each month where they were active (or active in the previous month), categorize their status change relative to the preceding month.

The categories for `Monthly_Status_Change` should be:
- `'New Subscriber'`: Customer was not active (no record) in the previous month but is active in the current month.
- `'Churned'`: Customer was active in the previous month but is not active (no record) in the current month.
- `'Upgraded'`: Customer was active in both months, and their `plan_tier` increased.
- `'Downgraded'`: Customer was active in both months, and their `plan_tier` decreased.
- `'No Change'`: Customer was active in both months, and their `plan_tier` remained the same.

The report should include `snapshot_month` (representing the current month of comparison), `customer_id`, `previous_plan_name`, `current_plan_name`, and `Monthly_Status_Change`.
Order the results by `snapshot_month` then `customer_id`.
The report should only include data up to the `snapshot_month` corresponding to the beginning of the month for the given `CURRENT_DATE`. (e.g., if `CURRENT_DATE` is '2024-03-15', the latest `snapshot_month` in the output should be '2024-03-01').

# Skills Tested
*   Complex JOIN strategies (e.g., self-join or full outer join logic for comparing records across months)
*   Date Manipulation (e.g., `INTERVAL` for shifting dates, handling `CURRENT_DATE`)
*   Conditional Logic (CASE statements for categorizing changes)
*   Handling NULLs to identify new subscribers and churned customers
*   Window functions (optional, but a common alternative approach to self-joins for this type of problem)
