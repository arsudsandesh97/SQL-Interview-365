# SQL Scenario-Based Interview Question: Identifying Dormant Premium Subscribers for Churn Prevention

## Business Scenario
You are a Data Analyst at 'SubscripTron', an E-commerce company offering a premium subscription service with exclusive benefits. The Product Management team is concerned about subscriber churn and wants to proactively identify 'dormant' premium subscribers who might be at high risk of cancelling. A subscriber is considered dormant if they are currently active, haven't utilized any premium features recently, AND haven't made a successful payment recently. The team needs a list of these subscribers, along with their last activity and payment dates, to initiate targeted re-engagement campaigns.

Assume:
```sql
CURRENT_DATE = '2023-10-26'
```

# Database Setup

## Create subscribers Table
```sql
CREATE TABLE subscribers (
    subscriber_id INT PRIMARY KEY,
    name VARCHAR(100),
    subscription_status VARCHAR(50), -- e.g., 'ACTIVE', 'CANCELLED', 'PAUSED'
    join_date DATE
);
```

# Task
Write a SQL query that identifies all 'dormant' premium subscribers.
A subscriber is considered **dormant** if ALL of the following conditions are met:
1. Their `subscription_status` is 'ACTIVE'.
2. Their last *recorded premium feature usage* was more than 45 days ago from `CURRENT_DATE`. If a subscriber has never used a premium feature (i.e., no records in `feature_usage` table for them), this condition should also be considered met.
3. Their last *successful payment* (`payment_status = 'Success'`) was more than 60 days ago from `CURRENT_DATE`.

The query should return `subscriber_id`, `name`, `join_date`, `last_feature_usage_date`, and `last_successful_payment_date` for all dormant subscribers. Order the results by `subscriber_id`.
