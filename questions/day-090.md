# SQL Scenario-Based Interview Question: Identifying Stagnant SaaS Subscriptions for Engagement

## Business Scenario
You are a Data Analyst at a SaaS company specializing in project management software. The Sales and Customer Success teams want to proactively identify "stagnant" subscriptions. These are long-term customers who have remained on their initial subscription plan without any upgrades or downgrades since their subscription began. Identifying these accounts can help the Customer Success team engage them for potential upselling opportunities (e.g., higher-tier plans with more features) or to understand why they haven't evolved their usage, potentially mitigating churn risk.

Assume:
```sql
CURRENT_DATE = '2023-10-26'
```

---

# Database Setup

## Create Subscriptions Table
```sql
CREATE TABLE subscriptions (
    subscription_id INT PRIMARY KEY,
    customer_id INT NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE, -- NULL if subscription is active
    current_plan_id VARCHAR(50) NOT NULL,
    initial_plan_id VARCHAR(50) NOT NULL
);
```

## Create Subscription History Table
```sql
CREATE TABLE subscription_history (
    history_id INT PRIMARY KEY,
    subscription_id INT NOT NULL,
    plan_id VARCHAR(50) NOT NULL,
    change_date DATE NOT NULL,
    change_type VARCHAR(50) NOT NULL -- e.g., 'NEW', 'UPGRADE', 'DOWNGRADE', 'CANCEL', 'RENEWAL'
);
```

# Task
Identify all active subscriptions that meet the following criteria for being "stagnant":
1.  The subscription is currently active (i.e., `end_date` is NULL or in the future relative to `CURRENT_DATE`).
2.  The `current_plan_id` is the same as the `initial_plan_id`.
3.  The subscription has been active for at least 2 years as of `CURRENT_DATE`.
4.  There has been NO 'UPGRADE' or 'DOWNGRADE' event recorded for this subscription in the `subscription_history` table since its `start_date`.

Return the `subscription_id`, `customer_id`, `start_date`, and `current_plan_id` for these stagnant subscriptions, ordered by `subscription_id`.
