# SQL Scenario-Based Interview Question: Identify At-Risk Subscription Customers

## Business Scenario
A leading E-commerce company offering subscription box services wants to proactively identify customers who are "at-risk" of churning in the near future. The Customer Success team needs a list of these customers to launch targeted retention campaigns. Your task as a Data Analyst is to define and extract this list based on specific criteria combining their current subscription status and past payment reliability.

Assume:
```sql
CURRENT_DATE = '2023-10-26'
```

---

# Database Setup

## Create Customers Table
```sql
CREATE TABLE Customers (
    customer_id VARCHAR(50) PRIMARY KEY,
    customer_name VARCHAR(100),
    email VARCHAR(100) UNIQUE
);
```

## Insert Customers Data
```sql

('C2', 'Bob Smith', 'bob@example.com'),
('C3', 'Carol White', 'carol@example.com'),
('C4', 'David Brown', 'david@example.com'),

```

## Create Subscriptions Table
```sql
CREATE TABLE Subscriptions (
    subscription_id VARCHAR(50) PRIMARY KEY,
    customer_id VARCHAR(50),
    plan_id VARCHAR(50),
    start_date DATE,
    next_renewal_date DATE,
    status VARCHAR(50), -- e.g., 'active', 'cancelled', 'expired', 'paused'
    FOREIGN KEY (customer_id) REFERENCES Customers(customer_id)
);
```

## Create Payment_Attempts Table
```sql
CREATE TABLE Payment_Attempts (
    attempt_id VARCHAR(50) PRIMARY KEY,
    subscription_id VARCHAR(50),
    customer_id VARCHAR(50),
    attempt_date DATE,
    amount DECIMAL(10, 2),
    status VARCHAR(50), -- e.g., 'successful', 'failed', 'pending'
    FOREIGN KEY (subscription_id) REFERENCES Subscriptions(subscription_id),
    FOREIGN KEY (customer_id) REFERENCES Customers(customer_id)
);
```

# Task
Identify all "at-risk" customers based on the following two criteria:
1. The customer has at least one *currently active* subscription (status = 'active') whose `next_renewal_date` is within the next 30 days (inclusive of the renewal date, from `CURRENT_DATE`).
2. For that customer, their *latest recorded payment attempt* (across *any* of their subscriptions) has a `status` of 'failed'.

Your query should return the `customer_id`, `customer_name`, and `email` of these at-risk customers, ordered by `customer_id`.
