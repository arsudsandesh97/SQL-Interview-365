# SQL Scenario-Based Interview Question: Identifying At-Risk SaaS Customers by Core Feature Disengagement

## Business Scenario
A SaaS product manager is concerned about potential churn among customers. They've identified a key indicator: a significant drop in engagement with the core "Dashboard Access" feature. They want to proactively identify users who meet two critical criteria indicating they are "at-risk":

1.  **Significant Drop in Core Feature Usage:** Their total usage count of the "Dashboard Access" feature in the *last 30 days* (up to `CURRENT_DATE`) is less than 50% of their *average daily usage* of "Dashboard Access" in the *previous 90 days* (i.e., the 90 days immediately preceding the last 30 days, so days 31-120 prior to `CURRENT_DATE`).
2.  **No Recent Exploration of Other Features:** They have *not used any other feature* (i.e., any feature apart from "Dashboard Access") in the *last 60 days* (up to `CURRENT_DATE`).

Your task is to provide a list of `user_id`s who match these criteria, along with the calculated usage metrics, to help the product team target their re-engagement efforts.

Assume:
```sql
CURRENT_DATE = '2023-10-26'
```

# Database Setup

## Create users Table
```sql
CREATE TABLE users (
    user_id VARCHAR(50) PRIMARY KEY,
    signup_date DATE
);
```


## Create feature_usage Table
```sql
CREATE TABLE feature_usage (
    usage_id INT PRIMARY KEY AUTO_INCREMENT,
    user_id VARCHAR(50),
    feature_name VARCHAR(100),
    usage_timestamp DATETIME,
    FOREIGN KEY (user_id) REFERENCES users(user_id)
);
```

# Task
Write a SQL query that identifies all "at-risk" customers based on the two criteria defined in the business scenario. The query should return the `user_id`, their `last_30_day_dashboard_usage` count, their `prev_90_day_avg_daily_dashboard_usage` (rounded to 2 decimal places), and a boolean `other_features_used_last_60_days` indicating if they used any feature *other than* 'Dashboard Access' in the last 60 days.

Sort the results by `user_id` in ascending order.

**Date ranges to use for `CURRENT_DATE = '2023-10-26'`:**
-   **Last 30 days:** `2023-09-27` to `2023-10-26` (inclusive)
-   **Previous 90 days (historical):** `2023-06-29` to `2023-09-26` (inclusive)
-   **Last 60 days (for other features):** `2023-08-27` to `2023-10-26` (inclusive)
