# SQL Scenario-Based Interview Question: Identifying Dormant High-Risk Subscribers

## Business Scenario
You are a Data Analyst at a growing SaaS company that offers various subscription tiers to its customers. The Customer Success team is concerned about potential churn from "dormant" users – those who are paying for a subscription but haven't actively used the core product features for an extended period. Your task is to identify these high-risk customers, segment them by their current subscription tier, and determine their last recorded activity date related to a core feature, or their subscription start date if they've never used the core feature. This list will be used for targeted re-engagement campaigns.

Assume:
```sql
CURRENT_DATE = '2023-10-26'
```

## Create users Table
```sql
CREATE TABLE users (
    user_id INT PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    signup_date DATE NOT NULL
```

## Create subscriptions Table
```sql
CREATE TABLE subscriptions (
    subscription_id INT PRIMARY KEY,
    user_id INT NOT NULL,
    tier VARCHAR(50) NOT NULL,
    start_date DATE NOT NULL,

```

# Task
Identify all active subscribers who have not engaged with any `core_feature_usage` activity for more than 60 days as of `CURRENT_DATE`.
For users who have never performed a `core_feature_usage` activity, consider the `start_date` of their *active* subscription as their "last activity date" for the purpose of calculating inactivity. However, only include users whose `days_inactive` (calculated using `CURRENT_DATE` minus their last core feature usage date, or their subscription start date if no core usage) is strictly greater than 60 days.

Your final output should include the `user_id`, `email`, `tier`, the `effective_last_activity_date` (which is either their last `core_feature_usage` date or their subscription `start_date` if they never used the core feature), and `days_inactive` (calculated as days between `effective_last_activity_date` and `CURRENT_DATE`). Order the results by `tier` (ascending) and then `days_inactive` (descending).
