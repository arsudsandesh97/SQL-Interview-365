# SQL Scenario-Based Interview Question: SaaS MRR and Active User Analysis with Prorated Plan Changes

## Business Scenario
As a Senior Data Analyst at 'CloudFlow Inc.', a growing SaaS company, you're tasked with providing critical insights into subscription performance. The finance and product teams need an accurate breakdown of Monthly Recurring Revenue (MRR) and active user counts per plan. A key challenge is that users can upgrade or downgrade their plans mid-month. The current reporting system doesn't accurately attribute revenue when plan changes occur within a billing cycle. Your goal is to generate a report that calculates the total MRR for each plan for each of the last few months, *prorating* the revenue based on the number of days a user was on a specific plan within that month. Additionally, you need to count the distinct active users for each plan per month, where an active user is defined as anyone who contributed any prorated MRR for that plan in that month.

Assume:
```sql
CURRENT_DATE = '2023-04-15'
```

# Database Setup

## Create Users Table
```sql
CREATE TABLE users (
    user_id INT PRIMARY KEY,
    user_name VARCHAR(50),
    registration_date DATE
);
```

## Insert Users Data
```sql
INSERT INTO users (user_id, user_name, registration_date) VALUES
(1, 'Alice', '2022-11-01'),
(2, 'Bob', '2022-12-05'),
(3, 'Charlie', '2023-01-10'),
(4, 'David', '2023-02-01');
```

## Create Plans Table
```sql
CREATE TABLE plans (
    plan_id INT PRIMARY KEY,
    plan_name VARCHAR(50),
    monthly_price DECIMAL(10, 2)
);
```

## Insert Plans Data
```sql
INSERT INTO plans (plan_id, plan_name, monthly_price) VALUES
(1, 'Basic', 10.00),
(2, 'Pro', 25.00),
(3, 'Enterprise', 50.00);
```

## Create Subscriptions Table
```sql
CREATE TABLE subscriptions (
    sub_id INT PRIMARY KEY,
    user_id INT NOT NULL,
    plan_id INT NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE, -- NULL if subscription is currently active
    FOREIGN KEY (user_id) REFERENCES users(user_id),
    FOREIGN KEY (plan_id) REFERENCES plans(plan_id)
);
```

# Task
Write a SQL query to calculate the `total_mrr` and `active_users` for each `plan_name` for each month between '2023-01-01' and '2023-03-31' (inclusive).
The MRR calculation must be prorated: for each user, calculate the portion of the `monthly_price` for each plan they were on during that month, based on the number of days they were active on that specific plan within the reporting month.
A user is considered 'active' for a given plan in a given month if they contributed any prorated MRR to that plan for that month.
The output should be ordered by `reporting_month` and then `plan_name`. `total_mrr` should be rounded to 2 decimal places.
