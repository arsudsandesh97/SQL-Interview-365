# SQL Scenario-Based Interview Question: Identifying Post-Downgrade Churn Risks in SaaS

## Business Scenario
A leading SaaS company, offering various subscription tiers, is concerned about customer churn. They suspect that customers who downgrade their subscription plan are at a higher risk of cancelling their service shortly after. As a Data Analyst, you've been tasked with identifying these "high-risk" customers to enable the customer success team to proactively intervene. Specifically, the team wants to find customers who downgraded their subscription and subsequently cancelled their service within 90 days of the downgrade.

Assume:
```sql
CURRENT_DATE = '2023-10-26'
```

---

# Database Setup

## Create Customers Table
```sql
CREATE TABLE Customers (
    customer_id INT PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    signup_date DATE NOT NULL
);
```

## Insert Customers Data
```sql
INSERT INTO Customers (customer_id, name, signup_date) VALUES
(1, 'Alice', '2022-01-01'),
(2, 'Bob', '2022-02-15'),
(3, 'Charlie', '2022-03-01'),
(4, 'David', '2022-04-10'),
(5, 'Eve', '2022-05-20');
```

## Create Plans Table
```sql
CREATE TABLE Plans (
    plan_id INT PRIMARY KEY,
    plan_name VARCHAR(255) NOT NULL,
    monthly_price DECIMAL(10, 2) NOT NULL
);
```

## Insert Plans Data
```sql
INSERT INTO Plans (plan_id, plan_name, monthly_price) VALUES
(101, 'Basic', 10.00),
(102, 'Standard', 25.00),
(103, 'Premium', 50.00),
(104, 'Enterprise', 100.00);
```

## Create Subscription_Events Table
```sql
CREATE TABLE Subscription_Events (
    event_id INT PRIMARY KEY,
    customer_id INT NOT NULL,
    event_type VARCHAR(50) NOT NULL, -- e.g., 'SUBSCRIBE', 'CHANGE_PLAN', 'CANCEL'
    plan_id INT, -- The plan after the event. NULL for 'CANCEL' events.
    event_date DATE NOT NULL,
    FOREIGN KEY (customer_id) REFERENCES Customers(customer_id),
    FOREIGN KEY (plan_id) REFERENCES Plans(plan_id)
);
```

# Task
Identify `customer_id`s who **downgraded their subscription plan** and then **cancelled their subscription within 90 days** of that downgrade.
A downgrade is defined as a `CHANGE_PLAN` event where the `new_plan_id` has a *lower* `monthly_price` than the `previous_plan_id` held by the customer immediately before the change.
For each such customer, return their `customer_id`, the `downgrade_date`, and the `cancellation_date`.
